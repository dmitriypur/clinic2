# Периоды цен приёма в виджете записи

## Результат для менеджера

У каждой взрослой и детской цены врача и филиала остаётся основное поле суммы. При вводе новой суммы без выхода из поля появляются обязательная дата начала (сегодня по умолчанию) и необязательная дата окончания, включительно. Ниже «Расписание цен» позволяет добавлять несколько цен на любые даты от сегодняшнего дня, редактировать строки и отменять отдельные изменения. Каждая новая цена сменяет предыдущую с даты начала. «Убрать цену» снимает собственную цену и все её будущие изменения, «Отменить изменения» возвращает редактор к сохранённому состоянию.

## Правила

- Виджет выбирает стоимость по выбранной дате приёма; до выбора даты использует сегодняшнюю дату.
- Существующие значения продолжают действовать без обязательного заполнения дат.
- Начало новой цены завершает действие предыдущей. Пустое окончание означает действие до следующего изменения.
- После указанного окончания старая цена автоматически не возвращается.
- Для каждой из четырёх цен можно добавить несколько предстоящих изменений без установленного ограничения количества. Для одной даты начала разрешена одна цена в категории; завершённые периоды сохраняются.
- Пустые цены допустимы. Когда нет подходящей цены ни у врача, ни у филиала, блок стоимости отсутствует, запись работает.
- Приоритет возрастной цены филиала и исключение врача из акций сохраняются. Для нетронутых настроек сохраняется прежняя подстановка API. Если прежняя цена филиала приходила из API, она продолжает действовать до первого запланированного изменения. После окончания или явного удаления управляемой цены внешний API не восстанавливает её.
- Сохранение других полей карточки не меняет цены и периоды.

## Реализация

1. Добавить тесты периодов, сохранения и явного удаления, затем реализовать общий обработчик расписания цен.
2. Хранить периоды в существующих JSON-полях `doctors.extra` и `cities.branches`, рядом с ценами. Изменение схемы БД и фоновые задания не нужны. При отмене будущего изменения предыдущий период восстанавливается естественно, поскольку окончание по следующему началу вычисляется при выборе цены.
3. Добавить общую группу полей Filament для врача и филиала и обработку создания/сохранения. Даты и действия редактора не попадают в публичные данные.
4. Передавать периоды вместе с данными врача/филиала. В общем frontend helper выбирать период до применения существующих приоритетов; подключить выбранную дату во всех трёх местах отображения.
5. Проверить связанные PHP/JS-тесты, сборку и локальные формы/виджет. Проверять границы периода, отмену, отсутствие всех цен, API fallback, возрастные категории, исключения, сохранение несвязанных полей и существующее обновление кеша.

## Ограничения

Заявки, UNF, маршруты, логика городов и общий механизм кешей не меняются. Сроки взрослой/детской цены независимы. Расчёт возраста остаётся существующим (на сегодня). До commit/merge требуется отдельное разрешение пользователя. Ветка: `feature/booking-price-periods`.

Стандартная live-привязка обновляет локальное состояние сразу, сохраняя встроенную задержку сетевого запроса. - Тесты запускались с изолированной SQLite в памяти и временным `LARAVEL_STORAGE_PATH`: штатный `storage` — ссылка на общее хранилище вне проекта. Общий прогон также выявил сбой существующего неизменённого теста `FrameSchoolSliderTest`, не связанного с ценами; по просьбе пользователя этот участок дальше не проверялся и не изменялся.
