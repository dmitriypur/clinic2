# BookingWidgetV3: Шаг Даты Рождения И Фильтрация Врачей

Документ фиксирует согласованный план для следующей доработки `BookingWidgetV3`, чтобы к реализации можно было вернуться без повторного сбора требований.

## Цель

После стартового шага `Что вам удобнее?` в `BookingWidgetV3` должен появиться новый обязательный шаг `Дата рождения пациента`.

После ввода даты рождения:
- в ветке `Выбрать врача` список врачей фильтруется по возрастным ограничениям врача;
- в ветке `Выбрать клинику` после выбора клиники/филиала список врачей тоже фильтруется по тем же правилам.

Фильтрация должна работать по новым structured age fields врача:
- `extra.age_min_months`
- `extra.age_max_months`
- `extra.receives_text`

Логика фильтрации не должна зависеть от старого текстового `extra.receives`.

## UX И Визуальный Вид

Новый шаг должен соответствовать макету:
- заголовок: `Дата рождения пациента`;
- одно поле ввода с маской `ДД.ММ.ГГГГ`;
- desktop:
  - две кнопки `Назад` и `Далее`;
- mobile:
  - большая кнопка `Далее`;
  - текстовая кнопка `Назад` снизу.

Шаг должен выглядеть как самостоятельный экран внутри модалки, а не как часть финальной формы.

## Новый Flow Виджета

Базовая схема:

1. `start`
2. `birth-date`
3. переход в выбранную ветку

Ветка `Выбрать врача`:

1. `start`
2. `birth-date`
3. `doctor-select`
4. `doctor-schedule`
5. `form`
6. `success`

Ветка `Выбрать клинику`:

1. `start`
2. `birth-date`
3. `clinic-select` или сразу `clinic-schedule`, если branch auto-skip
4. `clinic-schedule`
5. `form`
6. `success`

Важно:
- `bookingStartMode = doctor|clinic` тоже должен сначала открывать `birth-date`;
- шаг `birth-date` не должен быть жёстко привязан только к doctor/clinic flow, потому что позже после него добавится ещё одна ветка: `запись по выбору даты`.

## State И Архитектура

В `BookingWidgetV3` нужно добавить root-state:
- `selectedMode`
- `patientBirthDateDisplay`
- `patientBirthDateIso`

Где:
- `patientBirthDateDisplay` хранит строку в формате `ДД.ММ.ГГГГ`;
- `patientBirthDateIso` хранит строку в формате `YYYY-MM-DD`.

Нужен отдельный util для даты рождения, который:
- валидирует masked input;
- преобразует `ДД.MM.ГГГГ` -> `YYYY-MM-DD`;
- преобразует `YYYY-MM-DD` -> `ДД.MM.ГГГГ`;
- проверяет, что дата существует и не находится в будущем.

## Как Должна Работать Фильтрация

После успешного ввода даты рождения:

- doctor-flow:
  - загружаем врачей города через `bookingApi.getDoctorsByCity(cityId, birthDate)`;
  - затем поверх ответа API применяем локальную фильтрацию по `age_min_months` / `age_max_months`;
  - только после этого показываем `DoctorSelectStep`.

- clinic-flow:
  - клиники и филиалы работают как раньше;
  - когда нужно получить врачей клиники/филиала, используем `bookingApi.getClinicDoctors(clinicId, birthDate, branchId)`;
  - затем поверх ответа API применяем локальную фильтрацию по возрастным полям;
  - только после этого показываем список врачей.

Локальная фильтрация считается окончательной, даже если внешний booking API уже умеет фильтровать по `birth_date`.

## Правила Отсечения Врачей

Возраст пациента считается по введённой дате рождения.

Дальше сравнение идёт в месяцах:
- если `patientAgeMonths < age_min_months`, врач скрывается;
- если `age_max_months` задан и `patientAgeMonths > age_max_months`, врач скрывается.

Пример:
- дата рождения пациента: `03.05.2025`;
- врач принимает `с 2 лет`;
- у врача `age_min_months = 24`;
- такой врач должен быть исключён из списка.

## Последний Шаг Формы

На последнем шаге `PatientFormStep` поле даты рождения остаётся, но меняется его роль.

Новое поведение:
- поле даты рождения автозаполняется из шага `birth-date`;
- поле остаётся редактируемым;
- поле больше не является первичной точкой фильтрации списка врачей;
- при submit формы в API уходит текущее значение поля формы.

Допустимо оставить финальную защитную валидацию на последнем шаге как fallback от рассинхронизации, если пользователь вручную изменит дату после того, как список врачей уже был отфильтрован.

Но основная фильтрация должна происходить раньше, на шаге `birth-date`.

## Поведение При Пустом Результате

Если после фильтрации не осталось подходящих врачей:

- в `DoctorSelectStep` показываем empty-state с понятным сообщением;
- в `ClinicScheduleStep` показываем аналогичный empty-state;
- пользователя не уводим автоматически в `Оставить заявку`;
- пользователь может:
  - вернуться назад;
  - изменить дату рождения;
  - выбрать другой сценарий.

Рекомендованный текст:
- `Для указанной даты рождения подходящих специалистов не найдено`

## Требования К Реализации

Реализация должна быть:
- без дублирования date logic в нескольких компонентах;
- с единым util для преобразования дат;
- с root-state, а не со скрытой передачей даты между дочерними шагами;
- с явным разделением:
  - шаг выбора сценария;
  - шаг сбора даты рождения;
  - шаги выбора врача/клиники;
  - шаг финальной формы.

Нельзя делать реализацию, где:
- doctor filtering снова завязан на свободный текст `receives`;
- дата рождения хранится только внутри `PatientFormStep`;
- auto-open doctor/clinic обходит шаг даты рождения.

## Что Нужно Изменить В Коде

Минимальный состав изменений:

- `resources/js/components/BookingWidgetV3/BookingWidgetV3.vue`
  - добавить новый шаг;
  - добавить root-state даты рождения;
  - перестроить переходы между шагами;
  - прокинуть дату рождения в загрузку врачей;
  - автозаполнять `PatientFormStep`.

- новый компонент шага даты рождения в `resources/js/components/BookingWidgetV3/components/`

- новый util для даты рождения в `resources/js/components/BookingWidgetV3/utils/` или `resources/js/utilities/`

- `resources/js/components/BookingWidgetV3/components/DoctorSelectStep.vue`
  - empty-state для пустого filtered списка.

- `resources/js/components/BookingWidgetV3/components/ClinicScheduleStep.vue`
  - empty-state для пустого filtered списка врачей.

- `resources/js/components/BookingWidgetV3/components/PatientFormStep.vue`
  - дата рождения автоподставляется;
  - поле остаётся редактируемым;
  - логика фильтрации списка больше не живёт только здесь.

- `resources/js/services/bookingApi.js`
  - уже поддерживает `birthDate`, нужно использовать его стабильно из root-state.

## Acceptance Criteria

Фича считается сделанной, если:

1. После первого шага всегда появляется шаг даты рождения.
2. `bookingStartMode = doctor|clinic` тоже открывает сначала шаг даты рождения.
3. Поле ввода даты рождения соответствует макету и работает через маску `ДД.ММ.ГГГГ`.
4. Ветка `Выбрать врача` показывает только подходящих врачей.
5. Ветка `Выбрать клинику` показывает только подходящих врачей после выбора клиники/филиала.
6. При отсутствии врачей показывается empty-state, без автоперехода в `Оставить заявку`.
7. На последнем шаге поле даты рождения уже заполнено из шага 2.
8. На последнем шаге поле даты рождения можно редактировать.
9. При submit отправляется актуальное значение поля даты рождения из формы.
10. Архитектура не мешает позже вставить новую ветку `запись по выбору даты` после шага `birth-date`.

## Краткое Пояснение Для Возврата К Реализации

Нужно сделать так, чтобы дата рождения пациента выбиралась до показа списка врачей.

Дальше весь doctor selection должен строиться уже с учётом этой даты:
- сначала вводим дату;
- потом показываем только подходящих врачей;
- в финальной форме дата уже просто подставлена и может быть изменена пользователем, но она не должна быть единственным местом, где происходит фильтрация.
