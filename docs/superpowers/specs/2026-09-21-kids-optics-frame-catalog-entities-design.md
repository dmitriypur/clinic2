# Сущности каталога детских оправ

## Цель

Заменить временное хранение карточек в повторителе блока полноценным глобальным каталогом оправ, управляемым через Filament и пригодным для фильтрации и порционной загрузки без перезагрузки страницы.

## Рассмотренные варианты

1. Хранить бренд, цвета, возраст и пол в JSON внутри оправы. Это проще на старте, но администратор не сможет централизованно переименовывать и отключать значения, а в данных быстро появятся дубли.
2. Сделать универсальную EAV-систему характеристик. Она максимально гибкая, но неоправданно усложняет формы, запросы, валидацию и дальнейшее сопровождение.
3. Использовать отдельные справочники для изменяемых данных и enum для фиксированных значений. Это выбранный вариант: он обеспечивает нормальные связи и фильтрацию без лишней абстракции.

## Модель данных

- `FrameBrand`: название, порядок сортировки, активность. Одна оправа относится к одному бренду.
- `FrameColor`: название, HEX-цвет, порядок сортировки, активность. У оправы может быть несколько цветов через pivot-таблицу.
- `FrameAgeGroup`: название, код, порядок сортировки, активность. У оправы может быть несколько возрастных категорий через pivot-таблицу.
- `Frame`: бренд, модель, краткое описание, изображение Curator, фиксированный набор полов, ручной порядок, признаки «Хит», «Отличный выбор для школы» и активности.
- Пол хранится в JSON-массиве со значениями enum `boy` и `girl`. Оба значения означают «Любой пол».
- Размеров у оправы нет.

Справочники не удаляются из пользовательского интерфейса, если уже используются: ненужные значения отключаются. Это сохраняет целостность заполненного каталога.

## Административная часть

В Filament появляется группа «Каталог оправ» с ресурсами:

- «Оправы» — основная форма карточки;
- «Бренды»;
- «Цвета»;
- «Возрастные категории».

Форма оправы выбирает один бренд, несколько цветов и возрастов, один или оба пола, фотографию из Curator и флаги назначения. Ручная сортировка задаётся числом и поддерживается перетаскиванием в таблице.

## Публичный каталог

Блок хранит только собственные настройки: заголовок и подписи кнопки. Карточки берутся из активных оправ, отсортированных по `sort_order`, затем по `id`.

Первые шесть карточек рендерятся сервером для SEO и отсутствия скачка на десктопе. На мобильном до инициализации Vue CSS показывает четыре. Следующие карточки и результаты фильтра загружаются порциями через read-only API, которое возвращает готовую Blade-разметку карточек и метаданные пагинации. Разметка карточки остаётся в одном partial и не дублируется в JavaScript.

Возрастные и гендерные фильтры поддерживают множественный выбор. Выбранные возраста объединяются по OR. Один выбранный пол ограничивает каталог; два выбранных пола эквивалентны отсутствию ограничения. Повторное нажатие снимает значение. Возраст и пол применяются совместно по AND.

## Миграция временных данных

Миграция создаёт четыре основные и две pivot-таблицы, а также фиксированные возрастные категории. Существующие карточки из payload блоков каталога переносятся в новые сущности, включая Curator-изображения и цвета. После переноса публичный код больше не читает карточки из повторителя.

## Производительность и целостность

- Выборка использует eager loading бренда, цветов и возрастов.
- Индексы покрывают активность, сортировку, бренд и pivot-связи.
- API ограничивает размер порции и валидирует идентификаторы фильтров.
- Изображения продолжают использовать адаптивные Curator URL и фиксированное соотношение сторон.
- Каталог глобальный и не использует городские scope или привязки.
